# 서비스 상세 화면 개선안

상태: 1·2단계 구현·검증 완료 · 범위: Enter로 여는 서비스 상세 · 기존 승인 범위: 예측·예산·캐시 효율 분석 제외 유지

## 수정 전 문제

기존 상세 렌더러는 출처·관측 시각·리셋 문구만 표시했다. 요약의 게이지와 잔여 비율을 재사용하지 않아, 상세 진입 시 핵심 정보를 오히려 잃는다. 넓은 화면에서도 상세가 옆의 좁은 영역으로 제한된다. 현재 `↑/↓`는 상세 내용 스크롤이 아니라 서비스 선택에 연결되어 있어, 내용이 늘어나면 탐색 방식도 수정해야 한다.

## 기본 원칙

상세는 **요약의 정보를 모두 보존하고, 판단에 필요한 근거를 추가한다.** 정보가 없는 항목을 빈 그래프나 0으로 채우지 않는다. 계정의 구독 한도와 이 기기의 토큰 기록은 별도 구획으로 표시한다.

## 먼저 넣을 항목

| 항목 | 표시 내용 | 데이터 준비 상태 |
|---|---|---|
| 전체 한도 게이지 | 모든 창/모델 풀의 큰 게이지, 잔여·사용 비율을 함께 표시 | 기존 quota windows로 구현 가능 |
| 리셋 상세 | 남은 시간과 로컬 날짜·시각을 함께 표시. 알 수 없으면 미확인 | resets_at으로 구현 가능 |
| 한도 범위 설명 | 5시간/주간, 모델 또는 그룹 이름, 별도로 보고된 한도임을 구분 | window_minutes·label·id 활용. 관계가 확인되지 않으면 독립/공유 여부를 추정하지 않음 |
| 주의할 한도 | 잔량이 적거나 0%로 관측된 창을 명시. 오래된 값이면 최신 상태 아님을 함께 표시 | 현재 관측값으로 구현 가능. 사용 가능/차단 여부나 해제 시각을 단정하지 않음 |
| 조회 상태 | 마지막 정상 관측 시각, 이번 조회 성공/실패, 실제 사용한 출처, 자동 갱신 주기·정지 상태 | 기존 snapshot·config·화면 상태 활용 |
| 실패 원인과 다음 행동 | 조회 옵션 꺼짐, 로그인 필요, 타임아웃, 지원하지 않는 응답을 구분 | 기존 상태/메시지를 사용자용 문구로 정리. CLI 실패를 무조건 로그인 문제로 바꾸지 않음 |

게이지는 기본 설정(Remaining/Used)의 방향을 따르되 숫자는 잔여와 사용을 모두 제공해 해석을 돕는다. 예를 들어 `잔여 43.0% / 사용 57.0%`로 표시한다. 오래된 값은 마지막 관측값임을 명시하고, 이미 지난 리셋을 새 잔량으로 간주하지 않는다.

AGY는 Gemini, Claude/GPT, Argon을 구분한다. AGY의 Claude/GPT 풀을 Claude Code 구독 한도와 합치거나 같은 한도처럼 표현하지 않는다.

## 추가 가치가 있는 로컬 사용 정보

다음 항목은 새 인증 소스를 도입하지 않고 기존 이벤트 DB를 조회해 만들 수 있다. 서비스별 집계 데이터를 snapshot에 추가하고 서비스 필터를 적용한 조회를 연결했다.

| 항목 | 구성 | 제약 |
|---|---|---|
| 기간별 요약 | 오늘 / 최근 7일 / 최근 30일 토큰·API 환산 달러 | 이 기기에서 수집한 기록 범위. 현재 로그인 계정 전체의 사용량으로 표현하지 않음 |
| 토큰 구성 | 일반 입력·출력·캐시 읽기·캐시 쓰기 | 원시 저장 필드는 있으나 상세 집계 연결이 필요. 효율 점수나 절감액 분석은 추가하지 않음 |
| 최근 사용량 그래프 | 최근 24개 시간 구간의 토큰/달러 막대그래프 전환 | 이벤트 시각 기준. 수집 범위 미확인/부분 집계/미지원은 설명. 그래프를 위한 허구의 과거 값을 생성하지 않음 |
| 주요 모델·프로젝트 | 선택 기간의 모델/프로젝트 상위 3개와 토큰·달러 | 별도 분석 제품으로 확장하지 않고 원인을 짧게 설명하는 용도 |
| History 연결 | 현재 서비스와 기간을 유지한 채 전체 사용 이력으로 이동 | 현재 History의 서비스 필터 연결을 추가해야 함 |

사용자 추가 요청에 따라 달러 통계를 기간별 사용량의 기본 항목으로 포함했다. 정확한 모델 단가가 설정된 기록만 API 환산액을 계산한다. 전체 금액이 확인되면 `$금액`, 일부만 확인되면 `$확인된 소계 + ?`, 전혀 확인되지 않으면 `unknown`으로 표시한다. 미확인 이벤트 수를 함께 제공하고 토큰은 유지한다. 달러 그래프에 단가 미확인이 있으면 그래프를 감추고 토큰 그래프로 전환을 안내한다.

이 금액은 구독 결제액·잔액·공급자가 확정한 청구 금액이 아니다. `prices.json`의 입력·출력·캐시 읽기·쓰기 단가로 환산한다. 캐시 쓰기 기록이 있는데 쓰기 단가가 빠져 있으면 무료로 간주하지 않는다. 예산·절감액·캐시 효율 분석은 추가하지 않았다.

연결 계정의 마스킹된 표시명과 플랜도 유용한 후보이나, 현재 공통 snapshot에는 해당 정보가 없다. 공급자가 확인해 준 신원/플랜을 확보한 경우에만 표시하고 다른 앱의 로그인 계정과 같다고 추정하지 않는다. 이는 다중 계정 전환 기능을 추가하는 제안은 아니다.

## 이후 검토할 한도 추이 그래프

가장 유용한 후속 그래프는 선택한 한도의 잔여 비율이 시간에 따라 어떻게 변했는지 보여주는 것이다. **현재는 마지막 quota snapshot만 저장하므로 이 그래프에 필요한 과거 표본이 없다.**

도입하려면 정상 조회 결과를 시각·서비스·소스·버킷·윈도우/리셋 기준으로 추가 저장하고, 성공한 실제 관측만 점으로 표시해야 한다. 같은 캐시를 다시 읽은 것을 새 표본으로 넣지 않는다. 리셋·소스·계정 맥락이 바뀌거나 긴 수집 공백이 생기면 선을 끊는다. 계정 신원이 확인되지 않은 구간은 동일 계정의 연속 이력이라고 보증하지 않는다.

기록을 시작하기 전 구간은 `기록 없음`, 표본이 부족하면 `기록 수집 중`으로 표시한다. 이 그래프가 소진 예상 시각·남은 메시지 수 예측을 포함하는 것은 아니다.

## 화면과 조작

상세는 Enter로 전체 폭을 사용하는 전용 화면을 연다. 최소한 기본 화면의 모든 잔량·게이지·리셋을 유지한다. 넓은 터미널에서는 상세 내부에서만 구획을 좌우 배치하고, 좁은 화면에서는 세로로 배치한다.

권장 순서:

1. 서비스 이름과 최신성·주의 상태
2. 한도별 게이지, 잔여/사용 비율, 리셋 상대·절대 시각
3. 로컬 기간별 사용량과 선택한 사용량 그래프
4. 모델/프로젝트 상위 항목과 History 이동
5. 출처·실패 원인 등 조회 상세

`↑/↓`는 상세 내용 스크롤, `←/→`는 이전/다음 서비스, `r`은 갱신 요청, Enter/Esc는 목록으로 돌아가도록 한다. 한도 항목이 많은 AGY에서도 모든 항목에 접근할 수 있어야 한다. 자동 조회 주기와 공급자 재시도 제한은 구분해서 안내한다.

기본 화면에서는 기술 용어 `API`보다 `계정 직접 조회`, `AGY CLI 조회`, `로컬 스냅샷`처럼 출처를 이해할 수 있는 이름을 쓰고, 실제 엔드포인트·버킷 ID 등은 진단용 상세로 제한한다. 인증값이나 원본 응답은 표시하지 않는다.

## 권장 구현 순서

1. 요약 게이지 보존, 큰 잔여 수치, 리셋 날짜·시간, 조회 상태와 오류 설명, 상세 스크롤부터 수정한다.
2. 기존 DB를 이용해 서비스별 기간·토큰 구성·시간대별 사용량·상위 항목을 연결한다.
3. 실제 한도 관측 이력을 저장한 뒤 추이 그래프를 도입한다.

1·2단계와 달러 통계를 구현했다. 실제 한도 추이 그래프(3단계), 계정/플랜 정보는 데이터 수집이 준비될 때까지 대기한다. 모든 한도 게이지, 기간별 합계, 부분 단가, 시간 구간, 서비스 필터와 상세 스크롤을 회귀 테스트로 검증한다. 단가는 자동 추정하지 않으므로 사용자의 정확한 모델 단가 설정이 필요하다.
